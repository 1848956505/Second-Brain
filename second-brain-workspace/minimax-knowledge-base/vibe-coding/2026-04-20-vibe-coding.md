## 5. Vibe Coding的典型工作流

**来源**: HackerNews社区讨论  
**类型**: 方法论

### 推荐工作流

#### 阶段一：构思和规划（人）
1. 明确要做什么应用
2. 画简单的架构图
3. 确定技术栈
4. 拆解功能模块

#### 阶段二：脚手架（AI辅助）
1. 让AI生成项目结构
2. 设置基础配置
3. 安装依赖
4. 创建基础文件

#### 阶段三：功能实现（AI辅助）
1. 一个功能一个功能地实现
2. 每实现一个功能就测试
3. 及时发现和修复问题
4. 保持代码整洁

#### 阶段四：优化和重构（人+AI）
1. 功能完成后进行代码审查
2. 让AI提出优化建议
3. 重构明显的代码问题
4. 添加测试和文档

### 常见陷阱

| 陷阱 | 表现 | 解决方案 |
|------|------|---------|
| 需求不清 | AI写出不符合预期的代码 | 先明确需求再开始 |
| 范围蔓延 | 功能越做越多 | 控制每次迭代范围 |
| 不测试 | 直接部署出bug | 每个功能都要测试 |
| 全交给AI | 代码质量失控 | 人要参与关键决策 |
| 过度优化 | 花费太多时间 | 达到目标即可 |

## 6. AI Debug和重构技巧

**来源**: 社区实践总结

### Debug技巧

1. **错误信息直接给AI**
   ```
   这个错误是什么意思？
   [粘贴错误信息]
   ```

2. **最小复现**
   ```
   帮我创建一个最小可复现的示例
   ```

3. **代码审查**
   ```
   审查这段代码可能的问题
   ```

### 重构技巧

1. **分步重构**
   ```
   帮我重构这个函数，先从命名开始
   ```

2. **解释后再改**
   ```
   先解释这段代码做了什么，然后再优化
   ```

3. **保持功能不变**
   ```
   重构这段代码，但要保持功能完全一致
   ```

## 个人点评

Vibe Coding正在从"玩具"走向"生产力工具"，关键变化是：
1. 开发者学会了如何有效使用AI
2. AI工具变得越来越稳定
3. 工作流逐渐成熟

但要避免的极端：
- 完全不用AI：效率落后
- 完全依赖AI：质量失控
- 平衡点：AI处理常规任务，人做关键决策
